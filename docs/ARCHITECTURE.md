# Architecture and conventions

How the code is organised, and the rules that keep it maintainable. The *why* of each choice
is in [DECISIONS.md](DECISIONS.md) (ADR-015 covers this layout).

## Layout

```
src/triage/
  schema.py  prompts.py  dataset_map.py  textclean.py     the domain "contract": what a ticket
                                                          answer looks like, and the prompt
  paths.py      every file and folder, defined once
  io.py         read/write .jsonl helpers
  errors.py     UserError: a mistake the person running a command can fix
  settings.py   configs/models.yaml, loaded and validated (ModelEndpoint)
  llm.py        building an OpenAI client, the JSON-format option, the paid-call guard

  data/         turning raw tickets into datasets
    download.py  splits.py  mining.py  merge.py  gold_sheet.py  training.py  keywords.py
  labeling/     teacher.py (label tickets with a big model), pilot.py (compare candidates)
  evals/        metrics.py (the maths), runner.py (collect answers), scoring.py (report)

  cli.py        the `triage` command: parses options, calls one function
tests/          one fast test module per area; conftest.py has the fake model client
```

Dependencies point one way: `cli` → feature packages (`data`, `labeling`, `evals`) → shared
plumbing (`paths`, `io`, `settings`, `llm`) → the contract (`schema`, `prompts`). The contract
imports nothing from the rest.

## Rules

1. **No logic in the command line layer.** `cli.py` only parses options and calls a function. The
   function can then be tested without a terminal.
2. **No hard-coded paths.** Use `triage.paths`. Functions take paths as parameters with the
   project default, so tests can point them at a temp folder.
3. **No network or money in tests.** Model-calling functions accept a `client`; tests pass a
   `FakeClient`. Remote endpoints refuse to run without `--yes` (`require_approval_for_paid_calls`).
4. **One prompt everywhere.** Labelling, training, evaluation and serving all build messages with
   `prompts.build_messages`. Changing it is a decision (new ADR, schema version bump).
5. **Fail loudly, early, in plain words.** Config is validated on load (unknown keys are errors);
   user mistakes raise `UserError`; invalid model answers are *counted as wrong*, never skipped.
6. **Raw records are never edited.** The teacher's raw labels stay as they were; derived data
   (merged labels, training files) is regenerated by a command.
7. **Reproducible by construction.** Fixed seeds, content-hash ids, frozen test set (the splits
   command refuses to overwrite it).
8. **Readable over clever.** Plain loops and `if` blocks, one step per line, comments that say why.
   No comprehensions, lambdas, `**` unpacking or `X | None` type notes. The linter is set up not to rewrite
   code into shorter syntax (ruff `UP` rules are off on purpose).

## Workflow

```bash
uv run ruff check src tests && uv run ruff format --check src tests && uv run pytest
```

CI (`.github/workflows/ci.yml`) runs exactly these on every push and pull request.

To add a pipeline step: write a function in the matching package, add a handler and subparser in
`cli.py`, add a test that uses tmp folders and the fake client, add a step guide in `docs/steps/`.
